# README

## 1. サービス概要
「写真を撮る」「子供を選ぶ」「期限を選ぶ」の3タップ（文字入力ゼロ）で、学校プリントのタスク登録がすぐに完了するアプリです。

カレンダーやフォルダ分類などの多機能さをあえて徹底排除し、期限が近い順にプリント画像が並ぶだけの「挫折しないミニマル設計」に特化しています。

1つのアカウントを夫婦で共有してログインするため、面倒な家族招待の手間なくすぐに使用できるため、瞬時に情報の共有と分担が可能です。

## 2. このアイデアはどこから生まれたか
### 2-1. きっかけとなった体験・感情
長女が小学校に入学した際、保育園時代とのギャップによる配布物管理の負担に苦労したことがきっかけです。
保育園ではお便りはアプリ配信、提出物も先生からのリマインドがありましたが、小学校では毎日大量の紙プリント（学級だより、全校お知らせ、給食だよりなど）が配られ、リマインドも一切ありません。
提出期限や持ち物の情報が各プリントに散散しているため、必要な情報を探す時間が大きなストレスでした。
また、仕事で帰宅が遅い夫にすべてのプリントを読んでもらうのは難しく、管理負担が私一人に集中し、心身ともに大きな重荷となっていました。

### 2-2. なぜそれが「気になった」のか
私の中で、「在宅時間が長いから現状として私が家事・育児を多く担っているだけであって、家事・育児は私（妻）だけの仕事ではない」という強い思いがあるからです。
夫が家庭にコミットできるタイミングは、必ずあるはずと考えています。
また、万が一自分が体調不良などで動けなくなったときでも、家庭が円滑に回り続けるためには、夫婦間のフラットな情報共有が不可欠です。
学校からの大切なお知らせをブラックボックス化させず、「夫婦が同じ目線で、いつでも把握できる環境」を作りたいと考え、本アプリの開発を決めました。

## 3. 課題の整理
### 3-1. 表に見えている困りごと
学校からの大事な提出期限や持ち物の情報を見落とさないように管理できず、把握しきれないこと。

### 3-2. 本当に解決したい課題
なぜ？：子供が学校生活で困ったり、先生に迷惑をかけてしまったりするから。

なぜ？：迷惑をかけないために自分1人で完璧に管理しようと抱え込み、脳内疲労が生まれるから。

なぜ？：情報が自分にしか集約されていないため、夫に頼むことすらできず責任が集中するから。

解決したい課題：プリント管理の属人化をなくし、複数人（夫婦）でシームレスに共有・管理できる状態を作ることで、個人の負担を軽減し、時間と心の余裕を生み出すこと。

## 4. 想定ユーザーについて
### 4-1. 想定しているユーザー
年齢・状況：20代〜50代の子育て世代。仕事、育児、家事、介護など、最も多くのマルチタスクと役割を同時に抱え、時間のゆとりを求めている世代。

課題へのアプローチ：
日々の多忙さから、ゆっくり夫婦で情報共有する時間がない状況に対し、「文字入力を一切させない（写真を撮ってタグを選ぶだけ）」という極小コストの仕組みを提供し、疲れた夜でも挫折せず継続できるようにします。
また、アプリを開けば期限順にカードが並ぶため、夫もテキストを読み込むことなく優先度の高い情報を把握することができます。
説明コストを減らし、負担なくタスクが共有される環境を作ります。

### 4-2. 自分とユーザーの距離
距離感：自分自身、および身近な方（夫、ママ友など）

理由：私自身が直面しているプリント管理の限界は、同じ環境にいる子育て世代にとって共通の深い悩みであり、当事者だからこそ「本当に必要な最小限の機能」を追求できるから。

### 4-3. 実際に使われる可能性について（需要・存在確認）
今の代替手段と置き換える理由：
現在は「壁掛けカレンダー」や「家族LINE」が使われていますが、カレンダーは外出先で見られずリマインドもありません。LINEはお便り画像を共有できても、日常会話に埋もれてしまい検索や期限順の俯瞰が難しいです。本アプリは、それらのデメリットを同時に解消します。

### 4-4. ユーザーがサービスを導入して利用するまでのイメージ
導入のハードルを下げる工夫：ユーザー登録後、「家族招待・連携機能」を使わず、「1つのアカウントを夫婦で共有してログインする」ミニマルな仕様にすることで、導入の負担を減らします。
プリントを貰ったその場で3タップで登録が完了するため、無理なく習慣化し、1人への負担集中を防ぎます。

## 5. 既存サービス・競合調査
### 5-1. 似たサービスの調査
おたよりクリップ：画像登録、タグ付け、フォルダ分類が可能。

本アプリとの違い：分類・整理ができる反面、マメな入力が必要で多忙な時期に挫折しやすい。


プリゼロ：カレンダー連携、リマインド、OCR（文字認識）など非常に多機能。

本アプリとの違い：多機能な反面、画面の情報量や設定項目が多く、使いこなすまでの認知コストが高い。

### 5-2. それでも自分が作りたい理由
既存アプリは「マメに管理できること」を前提とした設定項目が多く、本当に忙しい日常においては、それらの入力作業自体が新たな「重いタスク」になっていました。「100%の綺麗な整理じゃなくていいから、すぐにプリントを放り込めて、期限だけを絶対に落とさないツール」が欲しいと感じたため、開発を決意しました。

### 5-3. 差別化を一文で決める
「忙しい日々の負担を減らす、機能を厳選した文字入力不要のプリント管理アプリ」

## 6. このサービスで提供したい価値
ユーザーの変化：プリント管理の煩雑さから解放され、時間・精神的な余裕が生まれます。管理は「ママの仕事」ではなく「夫婦のタスク」という認識に変わります。

価値を一文で表す：育児を筆頭にマルチタスクを抱える人たちが、学校からの配布物管理のストレスから解放されて、家庭内に時間的・精神的余裕を感じられるようになるサービス。

## 7. このアプリで実現すること（機能要件）
### MVPで作る機能
ユーザー登録・ログイン機能：メールアドレス、パスワードによる認証（1つのアカウントを共有）。

プリント画像登録機能：文字入力なし。「写真選択」「子どもタグ選択（第1子〜第3子/全体）」「期限日選択」の3タップで登録。

期限順一覧表示機能：登録された画像が、提出期限の近い順にカード形式で並ぶ。

プリント削除機能：確認・提出が終わったプリントを一覧から削除する機能（標準のCRUD処理）。

### 本リリース以降に実装する機能
パスワードリセット機能

編集機能

コメント入力／詳細なタグ追加機能

キーワード/タグ検索機能

「子どもタグ選択（第1子〜第3子/全体）」を任意の名前表示に変更できる機能

カレンダー連携、期限間近の通知/リマインド機能

複数アカウントによる「家族招待・連携機能」

ワンタップでの対応完了ステータス切り替え

リマインダー通知機能

## 8. このアプリの懸念点とその対策
懸念点：「文字入力をさせない（タイトルがない）」仕様のため、枚数が増えた際、年間予定表などの「長期保管したいプリント」を画像一覧から探しにくくなる可能性がある。

対策：MVP時は、直近の締め切り（当月内など）のプリントのみを優先表示し、終わったものはすぐ削除する運用でカバーします。本リリース以降に「長期保管用フラグ（ピン留め機能）」や「タイトル検索」を追加し、検索性を補完します。

## 9. 今後の展開・発展の方向性
子供が卒業するまで毎日発生する配布物に対し、生活の必須インフラとして機能させます。「タスク管理がラクになった」という成功体験をベースに、他の家庭内タスクの共有へと繋げます。

## 10. 技術スタック
### 10-1. 使用予定の技術
フレームワーク：Ruby on Rails7, JavaScript

DB：PostgreSQL

主要ライブラリ：Sorcery,CarrierWave,MiniMagick,Kaminari

デプロイ先：Render

### 10-2. 技術選定の理由
MVPの必須機能（CRUD、認証）はすべてRailsでの実装実績があり、バグの自己解決が容易なため。

限られた開発期間の中で、新しい技術の学習コストを抑え、確実に実装するため。

将来的な拡張（メール通知等）もRailsの標準機能で柔軟に対応可能なため。

### 10-3. キャッチアップ不足（今後の学習）の懸念と熱意
限られたスケジュールの中で確実に形にするため、まずはカリキュラム（基礎編）で何度も練習したRailsの基本機能を使って、MVPの確実な完成を最優先にします。

MVP完成後は、本リリースに向けて「タグでの切り替え」や「編集機能」の実装を通じ、カリキュラムの応用編（高度なRailsやJavaScript）への理解を深め、技術的にステップアップします。

まずは土台をしっかりと構築し、その後は応用編の課題やReactなどの新しい技術にも一歩一歩キャッチアップを続け、アプリをより使いやすく育てていく計画です。
